Q1 Tạo bảng và chọn kiểu dữ liệu thế nào? từ khóa: CREATE TABLE · BIGSERIAL · NUMERIC · TIMESTAMPTZ · TEXT

① CREATE TABLE: dựng khung

Hiểu nôm naKẻ bảng trên giấy trước khi điền: cột nào ghi số, cột nào ghi chữ, cột nào bắt buộc phải có.

CREATE TABLE users (
  id         BIGSERIAL PRIMARY KEY,
  email      TEXT NOT NULL UNIQUE,
  name       TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE IF NOT EXISTS ...;  -- không lỗi nếu đã có
DROP TABLE IF EXISTS users;      -- xóa cả bảng

Kiểu nên dùngBIGINT/BIGSERIAL cho id · NUMERIC(18,2) cho tiền · TEXT (nhanh như VARCHAR) · TIMESTAMPTZ · BOOLEAN · JSONB · UUID.

⚠ BẫyLưu tiền bằng FLOAT/REAL: 0.1 + 0.2 ≠ 0.3, số dư lệch dần. Dùng NUMERIC, hoặc BIGINT tính theo đồng.

Tự kiểmVì sao TIMESTAMPTZ an toàn hơn TIMESTAMP khi server và client khác múi giờ?

Q2 Ràng buộc dữ liệu ngay ở DB có những loại nào? từ khóa: PRIMARY KEY · FOREIGN KEY · UNIQUE · CHECK · ON DELETE

② Constraint: luật do DB tự giữ

Hiểu nôm naThủ thư không cho mượn sách nếu thẻ thư viện không tồn tại. App quên kiểm tra thì thủ thư vẫn chặn.

CREATE TABLE wallets (
  id      BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL
          REFERENCES users(id) ON DELETE RESTRICT,
  balance NUMERIC(18,2) NOT NULL DEFAULT 0
          CHECK (balance >= 0),
  version INT NOT NULL DEFAULT 0
);

ON DELETERESTRICT chặn xóa cha khi còn con · CASCADE xóa luôn con · SET NULL giữ con, FK thành NULL. Dữ liệu tiền chọn RESTRICT.

⚠ BẫyPostgres không tự tạo index cho cột FK (MySQL InnoDB thì có). Quên tạo thì JOIN hoặc xóa user sẽ quét cả bảng con.

Tự kiểmCHECK (balance >= 0) chặn được loại bug nào mà code Node có thể bỏ sót?

Q3 Thêm, xóa, đổi tên, đổi kiểu một cột thế nào? từ khóa: ALTER TABLE · ADD / DROP COLUMN · RENAME · TYPE

③ ALTER TABLE: sửa khung

Hiểu nôm naThêm cột "ghi chú" vào bảng điểm đã kẻ: kẻ thêm một đường, không cần chép lại cả bảng.

-- cột
ALTER TABLE wallets
  ADD COLUMN currency TEXT NOT NULL DEFAULT 'VND';
ALTER TABLE wallets DROP COLUMN currency;
ALTER TABLE wallets RENAME COLUMN balance TO amount;
ALTER TABLE wallets
  ALTER COLUMN balance TYPE NUMERIC(20,2);

-- ràng buộc trên cột
ALTER TABLE users ALTER COLUMN name SET NOT NULL;
ALTER TABLE users ALTER COLUMN name DROP NOT NULL;
ALTER TABLE users ALTER COLUMN name SET DEFAULT 'x';

-- constraint có tên
ALTER TABLE transactions
  ADD CONSTRAINT chk_amount CHECK (amount > 0);
ALTER TABLE transactions DROP CONSTRAINT chk_amount;

⚠ BẫyRENAME và DROP COLUMN có hiệu lực ngay, nhưng code cũ đang chạy vẫn gọi tên cũ nên lỗi. Phải deploy code trước, hoặc chia thành nhiều bước.

Tự kiểmThêm cột NOT NULL không có DEFAULT vào bảng đã có dữ liệu thì chuyện gì xảy ra?

Q4 ⭐ Thêm cột vào bảng 50 triệu dòng có phải ghi lại mọi dòng không? từ khóa: table rewrite · ACCESS EXCLUSIVE · metadata-only · volatile default

④ Ba loại ALTER: tức thì, quét, ghi lại

Hiểu nôm naThêm một trang vào cuối sách thì nhanh; đổi cỡ chữ cả cuốn thì phải in lại từng trang.

Tức thìADD COLUMN không default hoặc default là hằng số (từ Postgres 11, default lưu vào catalog, dòng cũ "mượn" giá trị đó) · DROP COLUMN (chỉ đánh dấu đã xóa) · RENAME.

Quét, không ghiSET NOT NULL · ADD CONSTRAINT CHECK / FOREIGN KEY: phải đọc mọi dòng để kiểm tra.

Ghi lại cả bảngALTER COLUMN TYPE phải đổi dữ liệu (vd. INT → TEXT) · ADD COLUMN … DEFAULT gen_random_uuid() (mỗi dòng một giá trị khác).

⚠ BẫyCái nguy hiểm là lock, không phải thời gian: phần lớn ALTER giữ ACCESS EXCLUSIVE, chặn cả đọc lẫn ghi suốt lúc chạy.

Tự kiểmXếp vào đúng loại: ADD COLUMN note TEXT, ALTER COLUMN id TYPE TEXT, SET NOT NULL.

Q5 ⭐ Thêm cột bắt buộc mà không downtime thì làm thế nào? từ khóa: expand / contract · backfill · batch

⑤ Thêm cột bắt buộc: chia 3 bước

Hiểu nôm naSửa đường mà xe vẫn chạy: làm từng làn, xong làn này mới rào làn kia.

-- 1. Thêm cột nullable → tức thì
ALTER TABLE transactions ADD COLUMN fee NUMERIC(18,2);

-- 2. Backfill theo lô, mỗi lô một transaction ngắn
UPDATE transactions SET fee = amount * 0.01
WHERE id BETWEEN 1 AND 10000 AND fee IS NULL;
-- ...lặp tiếp các lô sau

-- 3. Đủ dữ liệu rồi mới siết
ALTER TABLE transactions ALTER COLUMN fee SET NOT NULL;

Bên dướiBước 2 mới là chỗ "migrate từng record", nhưng chia nhỏ để không giữ khóa lâu. Trong lúc backfill, code phải chịu được cột còn NULL.

⚠ BẫyMột câu UPDATE cho cả 50 triệu dòng: transaction rất dài, khóa dòng lâu, sinh nhiều dead tuple.

Tự kiểmVì sao bước 3 vẫn chậm trên bảng lớn dù không ghi dòng nào?

Q6 Tạo index và kiểm tra query có dùng index không? từ khóa: CREATE INDEX · composite · CONCURRENTLY · EXPLAIN ANALYZE

⑥ Index và EXPLAIN ANALYZE

Hiểu nôm naMục lục sách: muốn tìm chữ "JOIN" thì tra mục lục, khỏi lật từng trang.

EXPLAIN ANALYZE
SELECT * FROM transactions WHERE wallet_id = 42;
-- Seq Scan = đọc cả bảng · Index Scan = tra mục lục

CREATE INDEX idx_tx_wallet ON transactions (wallet_id);
CREATE INDEX idx_tx_wallet_time
  ON transactions (wallet_id, created_at);
CREATE UNIQUE INDEX uq_wallet_user ON wallets (user_id);
CREATE INDEX CONCURRENTLY idx_tx_time
  ON transactions (created_at);   -- không khóa ghi
DROP INDEX idx_tx_wallet;

Bên dướiEXPLAIN chỉ in plan dự đoán; EXPLAIN ANALYZE chạy thật và in thời gian thật. Mỗi index làm INSERT/UPDATE chậm thêm vì phải cập nhật cả index.

⚠ BẫyCONCURRENTLY không chạy được trong BEGIN … COMMIT. Lỗi giữa chừng để lại index INVALID, phải DROP rồi tạo lại.

Tự kiểmIndex (wallet_id, created_at) có giúp query chỉ lọc theo created_at không? Vì sao?

FVMongo không có schema cố định nên ở FV bạn chưa phải lo ALTER khóa bảng: khối ④ ⑤ là phần mới thật sự. Index thì đã làm trên Mongo; compound index và leftmost prefix ở Mongo cùng ý tưởng với khối ⑥.

Summary

Chọn kiểu đúng ngay từ đầu: NUMERIC cho tiền, TIMESTAMPTZ cho thời gian, constraint để DB tự chặn dữ liệu sai; FK không tự có index. ALTER chia ba loại: tức thì, quét cả bảng, ghi lại cả bảng; cái đáng sợ là lock ACCESS EXCLUSIVE. Bảng lớn thì thêm cột nullable → backfill theo lô → siết NOT NULL, còn index thì tạo bằng CONCURRENTLY.

ADD COLUMN default tức thì theo Postgres 11+; ví dụ dùng schema lab users · wallets · transactions.
