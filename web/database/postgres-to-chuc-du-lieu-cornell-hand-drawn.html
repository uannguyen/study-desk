PostgreSQL: dữ liệu nằm ở đâu?

server → database → schema → bảng, và luật đặt tên đi kèm

1Tổ chức và đặt tên

Q1 SQL là chuẩn chung, vậy Postgres và MySQL khác nhau ở đâu? từ khóa: ISO SQL · dialect · default isolation · transactional DDL

① Chuẩn chung, phương ngữ riêng

Hiểu nôm naCùng là tiếng Việt, nhưng Bắc và Nam có từ riêng.

Bên dướiSQL là chuẩn ISO. Phần lõi (SELECT, JOIN, transaction) DB nào cũng có, phần còn lại mỗi DB một kiểu.

Ví dụPostgres: ON CONFLICT, RETURNING, DDL rollback được. MySQL: ON DUPLICATE KEY, DDL tự commit.

⚠ BẫyIsolation mặc định: Postgres là Read Committed, MySQL InnoDB là Repeatable Read.

Tự kiểmChạy SHOW transaction_isolation; và đoán trước kết quả.

Q2 ⭐ Connect vào DB lab, sao lại thấy 4 database? từ khóa: cluster · pg_database · template1 · template0

② Connect vào tòa nhà, đứng ở một tầng

Hiểu nôm naHost là địa chỉ tòa nhà, tên DB là tầng thang máy đưa bạn lên. Bảng chỉ dẫn ở sảnh thì liệt kê mọi tầng.

Bên dướiMỗi connection gắn đúng 1 database. Danh sách DB nằm ở pg_database, chung cho cả server. Đổi DB = mở connection mới (không có USE db).

Ví dụlab do POSTGRES_DB tạo · postgres là DB mặc định cho tool · template1 là khuôn để CREATE DATABASE sao chép · template0 là khuôn sạch, không sửa.

Tự kiểmCài extension vào template1 thì DB tạo sau có gì?

Q3 public, pg_catalog, information_schema là gì? từ khóa: schema · search_path · system catalog

③ Schema là phòng trong một tầng

Bên dướiThứ bậc: cluster → database → schema → table. Tên đầy đủ là public.users.

Ví dụpublic: bảng của bạn nằm đây, mặc định. pg_catalog: metadata riêng của Postgres (pg_locks, pg_constraint). information_schema: metadata theo chuẩn SQL, DB nào cũng có, ít chi tiết hơn.

⚠ BẫyỞ MySQL, schema và database là một. Ở Postgres là hai tầng khác nhau.

Tự kiểmĐứng ở DB lab, có SELECT được bảng của mini_wallet không? Vì sao?

Q4 ⭐ Viết hoa hay thường có quan trọng không? từ khóa: keyword · identifier folding · quoted identifier · string literal

④ Ba luật hoa thường

Bên dưới(1) Từ khóa: không phân biệt, viết hoa chỉ là quy ước. (2) Tên không có nháy kép: tự gấp về chữ thường. Có nháy kép: giữ nguyên, phân biệt chặt. (3) Chuỗi nháy đơn: phân biệt, 'vnd' ≠ 'VND'.

Ví dụCREATE TABLE Users tạo ra users. "VND" là tên cột, không phải chuỗi.

⚠ BẫyORM tạo cột "createdAt". Viết SQL tay WHERE createdAt sẽ báo không có cột createdat.

Tự kiểmĐặt tên snake_case, chữ thường, không nháy kép thì có bao giờ dính bẫy này không?

FVMongo chỉ có database → collection, không có tầng schema. Tự hỏi: PoC wallet-management (TypeORM) đặt tên cột kiểu camelCase hay snake_case?

Summary

SQL là chuẩn chung, mỗi DB có phương ngữ riêng; Postgres mặc định Read Committed. Một server chứa nhiều database, connection luôn đứng ở đúng một DB; trong DB chia tiếp thành schema, bảng của mình ở public. Tên không nháy kép bị gấp về chữ thường, còn giá trị chuỗi thì phân biệt hoa thường.

Kiểm chứng trên Postgres 18.6 (Docker lab). Ẩn dụ tòa nhà chỉ để nhớ, không phải thuật ngữ.
