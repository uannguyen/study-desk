1Bảng users · wallets

Q1 Primary key nên dùng bigint hay UUID? từ khóa: IDENTITY · UUIDv4 · UUIDv7 · B-tree locality

① Id tăng dần giữ index gọn

Bên dướibigint GENERATED ALWAYS AS IDENTITY sinh 1, 2, 3… (8 byte). UUID phải khai báo rõ: gen_random_uuid() (v4) hoặc uuidv7() (PG18).

Ví dụMongo ObjectId đầu là timestamp, giống UUIDv7: gần tăng dần.

⚠ BẫyUUIDv4 làm PK: insert rơi ngẫu nhiên khắp B-tree → page split, write chậm khi bảng vượt RAM. bigint lộ số lượng, đoán được id kế.

Tự kiểmNói được pattern "bigint nội bộ + UUIDv7 public" và lý do.

Q2 ⭐ Lưu tiền bằng kiểu gì? từ khóa: numeric · floating point · minor unit · bigint

② Tiền không bao giờ dùng float

Bên dướinumeric(18,2): thập phân chính xác tuyệt đối, 18 chữ số, 2 số lẻ. float là nhị phân: 0.1 + 0.2 ≠ 0.3.

Ví dụbalance numeric(18,2) NOT NULL DEFAULT 0 CHECK (balance >= 0). Hệ thống thật hay dùng bigint theo đơn vị nhỏ nhất (đồng, cent).

⚠ BẫyDriver pg trả numeric về string trong Node. Đó là chủ ý, không phải bug.

Tự kiểmVì sao balance phải NOT NULL? (gợi ý: NULL + 100)

Q3 Khai báo khóa ngoại cần lưu ý gì? từ khóa: REFERENCES · composite UNIQUE · FK index · leftmost prefix

③ FK cần kiểu, NOT NULL, và index tự lo

Bên dướiREFERENCES không thay được kiểu cột: phải viết user_id bigint NOT NULL REFERENCES users(id), cùng kiểu với cột được trỏ. FK cho phép NULL nếu không chặn.

Ví dụRàng buộc trên hai cột viết thành dòng riêng: UNIQUE (user_id, currency).

⚠ BẫyPostgres chỉ tự tạo index cho PRIMARY KEY và UNIQUE, không cho cột FK (MySQL thì có).

Tự kiểmTìm ví theo user_id có dùng được index của UNIQUE (user_id, currency) không?

Q4 DEFAULT 0 + CHECK (x > 0) sao tạo bảng không lỗi? từ khóa: DDL time · insert time · constraint evaluation

④ DEFAULT chỉ được tính lúc INSERT

Bên dướiLúc CREATE TABLE, default chỉ là biểu thức được lưu lại. Lúc INSERT mới tính ra giá trị, rồi mới chạy CHECK. DDL chỉ kiểm tra cú pháp và kiểu, không kiểm tra logic giữa các ràng buộc.

Ví dụamount của giao dịch: bỏ hẳn default, chỉ giữ NOT NULL CHECK (amount > 0).

Tự kiểmCột nào đáng có default? (gợi ý: balance ví mới, created_at)

Q5 Cột chỉ nhận vài giá trị (VND, USD) thì làm sao? từ khóa: CHECK IN · ENUM type · lookup table

⑤ Ba cách giới hạn giá trị

Bên dướiCHECK (currency IN ('VND','USD')): gọn, cho danh sách nhỏ ít đổi. ENUM: thêm giá trị dễ, xóa hoặc đổi tên khó. Bảng tra cứu + FK: thêm giá trị chỉ cần INSERT, dùng cho hệ thống thật.

⚠ BẫyChuỗi dùng nháy đơn. "VND" là tên cột.

Q6 Sửa một CHECK đang có thế nào cho an toàn? từ khóa: ALTER TABLE · transactional DDL · NOT VALID · VALIDATE

⑥ Xóa cũ, thêm mới, trong một transaction

Bên dướiTìm tên trong pg_constraint (mặc định wallets_balance_check). BEGIN; DROP CONSTRAINT …; ADD CONSTRAINT …; COMMIT; để không có khoảng hở. Postgres rollback được cả DDL.

Ví dụADD CONSTRAINT quét toàn bảng và giữ lock ACCESS EXCLUSIVE. Bảng lớn: ADD … NOT VALID trước, VALIDATE CONSTRAINT sau.

Summary

Id dùng bigint IDENTITY, tránh UUIDv4 làm PK; tiền dùng numeric hoặc bigint theo đơn vị nhỏ nhất, không bao giờ float. Ràng buộc (NOT NULL, CHECK, UNIQUE, FK) là tầng bảo vệ cuối, nhưng Postgres không tự index cột FK và không kiểm DEFAULT với CHECK lúc tạo bảng. Sửa constraint: drop + add trong một transaction; bảng lớn thì NOT VALID rồi VALIDATE.

uuidv7() có từ PostgreSQL 18, đã chạy thử trên container lab 18.6.
