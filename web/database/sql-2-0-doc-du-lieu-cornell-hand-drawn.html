Q3 Lọc dòng bằng WHERE: các toán tử hay dùng là gì? từ khóa: WHERE · IN · BETWEEN · LIKE · IS NULL

③ SELECT + WHERE: lấy cột nào, giữ dòng nào

Hiểu nôm naLọc ảnh trong điện thoại: chỉ hiện ảnh tháng này, có mặt bạn, ảnh mới nhất lên đầu, lấy 10 tấm.

SELECT id, amount, created_at
FROM transactions
WHERE type = 'debit'
  AND amount BETWEEN 100 AND 1000
  AND wallet_id IN (1, 2, 3)
  AND created_at >= date_trunc('month', now())
ORDER BY amount DESC
LIMIT 10;

⚠ BẫyWHERE col = NULL luôn ra rỗng vì NULL không bằng gì, kể cả NULL. Phải viết IS NULL.

Q4 ⭐ WHERE và HAVING khác nhau thế nào? từ khóa: GROUP BY · HAVING · COUNT · SUM · aggregate

④ GROUP BY: gom nhóm rồi mới tính

Hiểu nôm naĐổ kẹo ra bàn, chia vào từng hộp theo màu rồi đếm. Bỏ những hộp có ít hơn 5 viên.

SELECT wallet_id,
       COUNT(*)        AS so_gd,
       SUM(amount)     AS tong,
       MAX(created_at) AS gd_cuoi
FROM transactions
WHERE type = 'debit'   -- lọc DÒNG trước khi gom
GROUP BY wallet_id
HAVING COUNT(*) > 50   -- lọc NHÓM sau khi gom
ORDER BY so_gd DESC;

Hàm gomCOUNT(*) · SUM · AVG · MIN · MAX · COUNT(DISTINCT col).

⚠ BẫyCột nào trong SELECT không bọc trong hàm gom thì phải có trong GROUP BY, nếu không Postgres báo lỗi.

Q5 INNER JOIN và LEFT JOIN khác nhau thế nào? từ khóa: INNER · LEFT · ON · NULL · anti-join

⑤ JOIN: ghép hai bảng theo khóa

Hiểu nôm naDanh sách lớp ghép với danh sách nộp bài. INNER: chỉ bạn đã nộp. LEFT: cả lớp, bạn chưa nộp thì ô bài để trống.

-- INNER: chỉ giữ dòng khớp cả hai bên
SELECT u.name, w.balance
FROM users u
JOIN wallets w ON w.user_id = u.id;

-- LEFT: giữ hết bảng trái, không khớp thì NULL
SELECT u.name, t.id AS tx_id
FROM users u
LEFT JOIN wallets w      ON w.user_id = u.id
LEFT JOIN transactions t ON t.wallet_id = w.id;

⚠ BẫySau LEFT JOIN, đặt điều kiện của bảng bên phải ở WHERE sẽ loại mất các dòng NULL, kết quả thành INNER JOIN. Điều kiện đó phải để ở ON.

Q6 Subquery và CTE dùng khi nào? từ khóa: subquery · IN · WITH · CTE

⑥ Subquery và CTE: query lồng query

Hiểu nôm naBài toán dài thì giải nháp từng bước, đặt tên "kết quả bước 1" rồi dùng tiếp ở bước 2.

-- Subquery
SELECT * FROM wallets
WHERE id IN (SELECT wallet_id FROM transactions
             WHERE amount > 900000);

-- CTE: đặt tên cho kết quả trung gian
WITH tong_vi AS (
  SELECT wallet_id, SUM(amount) AS tong
  FROM transactions GROUP BY wallet_id
)
SELECT w.user_id, t.tong
FROM tong_vi t JOIN wallets w ON w.id = t.wallet_id
WHERE t.tong > 10000000;

Bên dướiTừ Postgres 12, CTE chỉ dùng một lần được planner gộp vào query chính như subquery, nên không chậm hơn. Chọn CTE vì dễ đọc.

Tự kiểmViết lại query CTE ở trên thành subquery đặt trong FROM.

FVLiên hệ Mongo: $match ≈ WHERE, $group ≈ GROUP BY, $lookup ≈ LEFT JOIN. Aggregation báo cáo NHNN bạn đã viết là cùng tư duy, chỉ khác cú pháp.

Summary

Postgres chạy FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT, nên alias chỉ dùng được từ ORDER BY. WHERE lọc dòng trước khi gom, HAVING lọc nhóm sau khi gom. INNER JOIN giữ dòng khớp cả hai bên; LEFT JOIN giữ hết bảng trái, điều kiện của bảng phải để ở ON. So sánh NULL bằng IS NULL, không dùng =.

Ví dụ chạy trên schema lab users · wallets · transactions; cú pháp theo Postgres 12+.
