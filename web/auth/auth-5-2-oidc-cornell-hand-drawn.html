5.2 · OIDC: OAuth2 thêm ID token

5.2 OIDC = OAuth2 + scope openid + ID token (trả lời 1.1)

1OIDC: biết ai đăng nhập

Q1 ⭐ OIDC khác OAuth2 chỗ nào? ID token khác access token ra sao? từ khóa: scope openid · ID token · sub · aud = client_id · SSO

5.2 OIDC = OAuth2 + ID token (là JWT, 4.2)

Nôm naOAuth2 đưa app chìa phụ. OIDC đưa thêm một tờ giấy: “người này là Lan, đăng nhập lúc 9h, giấy này dành cho app X”.

ChốtThêm scope=openid vào flow 5.1.1 → nhận thêm ID token cho app biết ai vừa đăng nhập.

Ví dụ
ID tokenAccess token
Ai đọcapp (client)API (resource server)
Trả lời“ai đăng nhập?” (1.1)“được làm gì?” (1.2)
audclient_id của appAPI
Áp dụng“Đăng nhập bằng Google” = Code + PKCE + openid. App verify ID token như mọi JWT (chữ ký, iss, aud = client_id của mình, exp, nonce), lấy iss + sub làm khoá liên kết user. Gọi API thì gửi access token.

⚠ BẫyLấy email làm khoá user: email đổi được, sub thì không.

Tự kiểm“Đăng nhập bằng Google” là OAuth2 hay OIDC? (OIDC chạy trên OAuth2)

FVService verify JWT do Keycloak ký bằng public key (Keycloak là OIDC provider). Tự hỏi: client có kiểm aud, nonce của ID token không?

Summary

OIDC thêm scope openid để nhận ID token, một JWT cho app biết ai vừa đăng nhập. ID token cho app, access token cho API; không dùng lẫn. Khoá user bằng iss + sub, không dùng email.
