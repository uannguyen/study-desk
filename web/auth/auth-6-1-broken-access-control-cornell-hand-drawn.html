Q1 ⭐ Broken Access Control là gì? Cho ví dụ và cách phòng. từ khóa: A01 · IDOR · privilege escalation · deny by default

6.1 Broken Access Control → hỏng nhánh 1.2

Nôm naThẻ phòng 305 mà mở được cả phòng 306, vì ổ khoá chỉ kiểm “có phải thẻ của khách sạn không”.

ChốtServer không kiểm, hoặc kiểm thiếu, “bạn được làm gì trên tài nguyên này”. Đứng số 1 OWASP Top 10:2025.

Ví dụ
user A · GET /orders/124 (đơn của B)→✗ 200: IDOR
user thường · PUT /users/42 { "role": "admin" }→✗ thành admin
Trang /admin chỉ ẩn link trên menu→✗ gõ URL là vào
Áp dụng
  • Deny by default: route mới mặc định cấm, mở quyền rõ ràng.
  • Lọc theo chủ sở hữu ngay trong query: WHERE id = ? AND user_id = req.user.id.
  • Whitelist field được sửa, không nhận role từ body.
  • Test: đăng nhập user A, gọi bằng id của user B.

Tự kiểmẨn nút “Xoá” trên UI có phải là phòng chống A01 không? (không, kiểm ở server mới tính)

FVTự hỏi: API nào lấy tài nguyên theo id trên URL? Query đã lọc theo chủ sở hữu chưa, hay chỉ kiểm “đã đăng nhập”?

Summary

Broken Access Control là nhánh 1.2 bị hỏng: không kiểm “tài nguyên này của ai”. Phòng bằng deny by default, lọc theo chủ sở hữu ngay trong query, whitelist field được sửa. Ẩn nút trên UI không tính.

Nguồn: OWASP Top 10:2025 (A01). Trước: 6.0 Tổng quan · Tiếp theo: 6.2 Cryptographic Failures.
